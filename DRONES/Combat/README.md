# Fighter drones
**FD1-B, FD2 and FD4: source implemented / awaiting owner validation. FD3 patrol is intentionally deferred.**

Complete a [Drone Station](../../TOWERS/Utility/DroneStation/README.md), buy a fighter, select its slot and LAUNCH. Auto-pilot intercepts detectable enemies with the smallest remaining journey to their assigned Citadel, then follows them with target-relative figure-eight, orbit and kiting passes. Comparable threats are distributed between fighters, with hysteresis and urgent breach priority. Between waves they guard near home; RECALL docks without refilling HP/ammo.

**FD4 weapon:** each launched fighter uses an independently rotating `Body/GunPivot` mini-gun and a physical `Body/GunPivot/Muzzle`. Targets within its configured range, aligned within the aim tolerance and visible over the **same shared terrain weapon LOS** as towers receive real non-homing Kinetic `BasicProjectile` rounds. The shot renderer now recognizes the original Gunner's **tapered energy-streak geometry** for friendly rounds. `Artwork/FighterBlueTracer.tres` uses the original Gunner proportions/rounded core/tail fade but a **blue/cyan** core/body/glow; `Artwork/FighterBlueMuzzleFlash.tres` supplies the matching short blue flash. `FighterDroneWeapon` uses the shared world projectile parent, no per-drone bullet manager, enemy search or own physics loop.

**Provisional tuning (`DefaultFighterDroneConfig.tres` / `FighterDroneConfig.cs`):** 275px weapon range, 4 Kinetic damage per shot, 5 shots/s, 1200px/s speed, 540°/s gun turn, 10° alignment tolerance, 200 total rounds from existing fighter config. One round is deducted only after a projectile is launched. No automatic reload: the ammo display reaches zero and stays there until future **FD5 station supply**. The fighter's `DamageSource` is a separate weak fighter identity; kills still award the game's normal credits, but **do not grant tower rank XP** or invent a fighter XP progression.

`FighterDroneTargeting` belongs to the world's enemy registry: one shared 96-candidate-per-physics-frame budget, top-64 cache refreshed after 0.25s, plus per-fighter staggered search intervals. Only deployed station managers drive it. `FighterDroneMovement` owns continuous steering; shared `DroneFlightMotion` retains finite launch/return and `DroneBody` retains engines/trails. Tune auto-pilot speed, acceleration/braking, turn rate, attack distance, orbit radius, manoeuvre speed, lead and search interval in the fighter config.

Checkpoint state retains ID, slot, HP/ammo, pose, flight leg, velocity and loop phase; FD4 adds optional positive `WeaponCooldown` so an in-progress cadence doesn't reset on restore. Targets are reacquired. Existing state enum values and older missing cooldown default remain compatible. The usual content-hash compatibility checks still apply after source changes. Station sale/destruction cleans up fighters and assignments.

**Not implemented:** FD3 two-click patrol controls, FD5 resupply/repair, fighter XP, hostile anti-air. [Roadmap](FIGHTER_DRONES_IMPLEMENTATION_PLAN.md). Full gameplay/FPS acceptance belongs to owner.
