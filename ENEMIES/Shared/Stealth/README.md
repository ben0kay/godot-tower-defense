# Enemy stealth and directional reveal — SE1 / SE2

Waves opt in independently of shields: `Enemy("basic_mk1", shield: true, stealth: true)`. Default is false for every existing wave/F2 spawn. The flag passes through immutable WaveEnemyEntry, WaveManager and both SpawnManager.SpawnWave overloads to Enemy.Initialize's appended optional spawnWithStealth argument. EnemyDefinition and shared authored enemy resources are not mutated. Carrier children remain independently configured ordinary spawns; parent stealth does not silently propagate.

Enemy.HasStealth is the underlying capability. Enemy.IsEffectivelyStealthed means that capability exists and its EnemyStealthState has zero reveal sources. Stealth is a separate detection capability, not Slow/Freeze, shield points, damage immunity or a status timer. EnemyStealthState uses stable source identities; AddReveal/RemoveReveal are idempotent and only zero↔one transitions notify presentation. Future non-beacon sources can reuse this contract and must release their own handles.

StealthRevealSystem is one lazy child under the world's EnemyRegistry, created by a beacon. It spatially indexes beacon coverage using256px buckets and uses the existing enemy spatial index on beacon activation/config/position changes and on capped directional heading samples. Enemy registration/transform/removal events update membership; movement tests only nearby source buckets plus existing memberships. Normal enemies take a capability fast path. When no beacons are active it unsubscribes from movement. No per-enemy node, all-enemy scan per frame or physics Area2D is introduced. SE2 gives each operational beacon an asleep-when-inactive rotation/accumulator callback; this reveal index itself has no frame callback.

Leaving one cone or its range removes only that source. Overlapping sources keep enemies revealed until all leave. Construction/upgrading/disabled/destroyed/removed beacon releases coverage immediately; reactivation finds stationary enemies. Teleports and source range edits refresh coverage. Enemy death/arrival/reinitialization and world teardown release both sides. Pause freezes scanner heading and detection refresh; there is no timed reveal expiry.

Visibility lives in FEEDBACK/Stealth; target eligibility in TOWERS/Shared/Detection; source scene/config in TOWERS/Utility/StealthBeacon. See TESTS/Stealth/README.md for real placement, wave and weapon checks. No existing map or authored wave has been changed to introduce stealth automatically.

## SE2 implementation — 2026-11-05

`Area` retains normalized Forward, Radius/RadiusSquared and cached half-angle cosine. Movement, new stealth spawns and current-member expiry use the same inclusive cone predicate. Normal enemies exit before source-bucket lookups. Direction samples query only nearby candidates using `GetEnemiesInRadius` and reusable storage, then diff that one Area's members. Retained reveal handles are untouched, and former members not returned at the new location are removed. Empty source lists are recycled, avoiding repeated list allocation as ships re-enter a sweeping cone. Register/config/teleport updates preserve an existing Area identity; ordinary heading updates never unregister/re-register it.

Default 70°/256px scan rotates every 3s and refreshes at 0.1s. This is discrete detection at the latest sampled heading, continuous visual rotation, and no passive detection bubble. Shared `TowerDetection` acquisition/cached-lock rules remain unchanged; losing the final reveal makes ordinary aimed attacks ineligible on their next normal validation. Independent non-beacon sources still compose through EnemyStealthState.

Source checks only; .NET build/runtime/visual acceptance remains for owner. See [updated focused checks](../../../TESTS/Stealth/README.md) and [beacon plan](../../../TOWERS/Utility/StealthBeacon/DIRECTIONAL_SCAN_IMPLEMENTATION_PLAN.md).
