# Repair Tower — Restoration Tower (RT0 foundation implemented)

The planned **Restoration Tower** is a 1×1 rotating laser support tower with sleek white/silver artwork and pale aqua detailing. It seeks damaged **friendly towers**, not enemies, and continuously repairs structural hull with a muzzle-origin beam when aligned and funded. The old Vector TD 2026 **Restoration Array** inspired its lowest-integrity targeting and energy-based repair, but the modern tower uses the existing shared Godot targeting/aiming, durability, heat, construction and later capacitor-based power infrastructure.

**Authoritative staged design:** [RT0–RT4 implementation plan](IMPLEMENTATION_PLAN.md). Codex should read this plan plus `NOTES/CodePreferences.md` and implement **only the requested pass** on `dev`. **RT0 is Source Implemented / Awaiting Owner Validation:** shared friendly acquisition and fast lock validation live in `TOWERS/Shared/Targeting/`. No playable repair turret exists in this folder yet; RT1–RT4 remain planned.

Phase overview: RT0 friendly spatial targeting → RT1 playable repair turret/beam → RT2 shared heat + real PW4 power integration when available → RT3 purchased tiers/Inspector and friendly priority options → RT4 optional Citadel/shield/mobile repair after separate approval. PW4-A currently provides Battle Tower's projectile-funded capacitor; a future repair beam must extend that shared funding seam for actual repair seconds rather than invent another energy system. Distance/priorities/Inspector power work remains separate.


RT0 selects lowest finite hull fraction with registration-order ties, using the existing TowerRegistry and caller-owned scratch list. It excludes self/full/dead/queued/detached/busy targets, uses root-to-root range and permits damaged EMP/heat/NoPower-disabled targets. A disabled/busy healer cannot acquire or retain a valid repair lock. No enemy policy, HUD, catalog, stats or combat behavior changed.
